# Shipment Control Tower
> 판매·생산 정보 통합 및 선적 리스크 관리 웹사이트

## 1. 프로젝트 개요

LG전자 AX 스쿨 개인 프로젝트로, 물류·영업기획(SCM, APM) 실무 경험을 바탕으로 개발하는 웹사이트입니다.

판매법인과 생산법인에서 전달하는 서로 다른 형식의 엑셀 파일, 메일 본문, 캡처이미지를 표준화하고 서로 연결하여 판매계획부터 생산, 선적, ERP 매출화 확인까지 관리하는 것을 목표로 합니다.

현재 상태는 **기본 사이트, 판매자료 업로드·표준화, PSI 버전 비교와 주문 RISK 수동 승인 단계 구현 완료**입니다. 아래 기능 전체는 장기 구현 목표이며, 실제 구현 여부는 [requirements.md](requirements.md)에 별도로 기록합니다.

## 2. 해결하려는 업무 문제

### 2.1 판매계획 취합

- 판매법인마다 파일 양식과 컬럼명이 다릅니다.
- 자료가 매일 또는 2~3일 간격으로 갱신됩니다.
- 동일한 주문도 행 순서와 분할 방식이 달라집니다.
- 기존 자료를 다시 복사하고 정리하는 작업이 반복됩니다.
- 판매계획에 신규 물량이 추가되거나 기존 물량이 감소·취소될 수 있습니다.

예를 들어 동일한 PO·고객·모델의 20대가 오늘은 `15대 + 5대`, 내일은 `20대`로 전달될 수 있습니다. 이 경우 표시 방식 변경과 실제 판매계획 변경을 구분해야 합니다.

### 2.2 생산·선적 정보 연결

- 생산법인마다 파일 양식이 다릅니다.
- 생산정보와 선적정보가 서로 다른 파일 또는 시트로 전달됩니다.
- 일부 정보는 메일 본문이나 이미지로 전달됩니다.
- PO번호가 없는 자료도 있습니다.
- 모델, 고객, 수량, 생산사이트 등을 대조하여 판매계획과 연결해야 합니다.
- 부분 생산과 부분 선적으로 주문 하나에 여러 일정이 존재할 수 있습니다.

### 2.3 위험 및 매출화 확인

- 판매계획은 있지만 생산·선적계획이 없는 물량을 발견해야 합니다.
- SP에 맞춰 실제 선적이 가능한지 확인해야 합니다.
- 생산완료 후 선적계획 없이 대기하는 물량을 찾아야 합니다.
- 실제 선적 이후 ERP 매출화가 완료되었는지 별도로 확인해야 합니다.

## 3. 프로젝트 목표

로그인 사용자는 여러 SCM 프로젝트를 목록으로 구분합니다. 새 업무는 기존 자료가 하나도 없는 빈 프로젝트로 시작할 수 있고, 현재 Sales Master 상태가 필요한 경우에만 사본을 만듭니다. 프로젝트 소유자는 프로젝트 이름을 다시 확인한 뒤 프로젝트 전체를 영구 삭제할 수 있으며, 다른 프로젝트와 공유 원본은 영향을 받지 않아야 합니다. 마지막 프로젝트는 삭제하지 않고 먼저 새 빈 프로젝트를 만들도록 안내합니다.

1. 서로 다른 판매법인 자료를 표준 Sales Master로 통합합니다.
2. 생산법인 자료와 메일에서 생산·선적 정보를 추출합니다.
3. 주문과 생산·선적 물량을 수량 기준으로 연결합니다.
4. 확실한 정보는 자동 반영하고 모호한 정보는 검토 대상으로 분류합니다.
5. 판매계획의 추가·감소·취소·월 이동을 이력으로 관리합니다.
6. PSI의 주차별 SP와 실제 선적 실적을 비교합니다.
7. 업무 규칙에 따라 위험과 확인 필요 항목을 표시합니다.
8. Sales Master를 Excel로 다운로드합니다.
9. Gmail 연동 후 일일 자동 수집·업데이트를 지원합니다.
10. 처리 근거와 검증 결과를 보여주는 포트폴리오를 완성합니다.

## 4. 기본 업무 흐름

판매자료 입력  
→ 컬럼 매핑 및 표준화  
→ 기존 판매계획과 변경 비교  
→ 판매계획 반영  
→ 생산·선적 자료 입력  
→ 정보 추출 및 매칭  
→ 자동 확정 또는 사용자 검토  
→ PSI·RISK·ERP 매출화 현황 확인  
→ Sales Master Excel 다운로드

수동 업로드를 기본으로 제공하고, Gmail 자동 수집은 같은 처리 흐름에 연결합니다.

## 5. 입력 자료

| 구분 | 입력 방식 | 주요 내용 |
|---|---|---|
| 판매계획 | XLSX, XLS, CSV | PO, 모델, 고객, 가격, 수량, 사이트, 지역 |
| 생산정보 | 엑셀, 메일 텍스트, 이미지 | 모델, 고객, 수량, 생산일, 가능한 경우 PO |
| 선적정보 | 엑셀, 메일 텍스트, 이미지 | 모델, 고객, 수량, 선적일, 선사 등 |
| PSI | 엑셀 | 주차별 DM, SA, SP 및 계획 버전 |
| ERP 확인 | 파일 또는 근거가 있는 수동 입력 | 매출화 상태, 수량, 금액, 확인일 |
| Gmail | 사용자 계정 연결 | 메일 본문과 첨부파일 |

여러 파일, 여러 시트, 서로 다른 헤더 위치를 지원하는 것을 목표로 합니다.

생산정보와 선적정보가 한 파일에 함께 있으면 파일을 억지로 한 유형으로 합치지 않습니다. 같은 파일을 먼저 `생산정보`, 다음에는 `선적정보`로 각각 저장하여 서로 다른 매핑·검증 흐름으로 검토합니다. 같은 파일을 같은 유형으로 반복한 경우만 중복으로 처리합니다.

## 6. 표준 관리정보

### 6.1 판매 기본정보

- 내부 주문 ID
- 판매법인
- 대상 매출 월
- PO번호
- PO라인번호: 제공된 경우
- 모델명
- 고객명
- 수량
- Net Sales
- Gross Sales
- 가격 구분: 단가 또는 총액
- 통화는 파일 컬럼을 요구하지 않고 USD 공통값으로 적용
- 생산사이트
- 판매지역
- 자료 기준일
- 원본 출처 및 판매계획 버전

PO번호는 문자열로 저장하여 앞자리 `0`을 보존합니다.

Net Sales와 Gross Sales가 단가인지 총액인지 확인한 후 계산합니다. 현재 Sales Master 표시·신규 반영 기준 통화는 USD 하나이며 판매자료 업로드에서 통화 컬럼을 요구하거나 매핑하지 않습니다. 다른 통화를 지원하려면 별도의 환율·환산 기준 설계를 먼저 추가해야 합니다.

### 6.2 생산·선적 정보

- PST(생산예정일)
- 실제 생산완료일
- 생산예정수량
- 실제 생산완료수량
- ETD(선적예정일)
- 실제 선적일
- 선적예정수량
- 실제 선적수량
- 선사
- 선박명
- 항차
- 컨테이너번호
- B/L번호
- 정보 출처 및 확인 상태

예정과 실제 완료를 구분합니다. 현업 생산·선적계획에 별도 완료 플래그가 없으므로 프로젝트 상단에서 사용자가 정한 기준 날짜보다 과거인 PST·ETD가 최신 파일에 계속 기재되고 안전하게 주문과 연결된 행은 해당 수량을 각각 실제 생산·실제 선적으로 봅니다. 일부 물량만 과거 일정이면 그 수량만 완료 처리합니다. 기준 날짜를 바꾸면 화면과 Excel의 상태를 다시 계산하되 원본 일정은 변경하지 않습니다.

PST와 ETD는 서로 다른 업무 날짜로 보존합니다. Shipment 물량의 ETD 화면에는 확인된 선사명과 선박명을 함께 표시합니다. ETA는 현재 화면·업로드 매핑·API 응답·Excel에서 제거하며 기존 데이터베이스 값만 호환을 위해 보존합니다.

선사명만으로 선박 위치를 확정하지 않습니다. 위치 조회는 식별정보와 외부 서비스 연결이 확보된 경우에 제공합니다.

### 6.3 ERP 매출화 정보

- 상태: 미확인 / 미완료 확인 / 일부 완료 / 전체 완료 / 취소·정정
- 매출화 확인수량
- 매출화 확인금액 및 통화
- 확인일
- ERP 문서번호: 제공된 경우
- 확인자
- 확인 근거

선적예정일 경과나 실제 선적만으로 매출화 완료를 추정하지 않습니다.

한 번 근거를 확인해 `Closed`로 저장한 ERP 매출화 수량은 판매법인의 새 판매자료에 값이 없거나 값이 달라도 자동으로 취소·초기화하지 않습니다. 후속 파일은 버전 비교 대기로 보존하고, Closed 정정은 별도의 근거 있는 `취소·정정` 절차에서만 처리합니다.

## 7. 데이터 관리 원칙

### 7.1 원본과 표준 데이터를 분리합니다

원본 파일·메일, 추출 행, 표준 주문, 생산·선적 물량, 연결 내역, 변경 이력을 별도로 보존합니다.

원본의 파일명·시트·행 또는 메일 식별정보를 통해 처리 근거를 확인할 수 있어야 합니다.

### 7.2 행 번호를 주문 식별자로 사용하지 않습니다

엑셀의 정렬이나 행 분할이 달라져도 내부 주문과 기존 생산·선적 연결은 유지되어야 합니다.

### 7.3 주문과 물량 연결을 분리합니다

주문 20대에 생산 15대와 5대, 선적 10대와 10대를 각각 연결할 수 있어야 합니다.

생산과 선적은 서로 다른 단계의 실적입니다. 같은 물량이 각 단계를 통과하는 것은 허용하되, 같은 단계에서 중복 배분되면 안 됩니다.

### 7.4 수량과 금액을 대사합니다

- 원본 수량·금액과 표준화 결과를 비교합니다.
- 처리·제외·오류·검토 행을 모두 추적합니다. 오류·검토 행은 원본 셀과 사유를 화면에 표시하며, 사용자가 명시적으로 확인한 비업무 행은 원본·사유를 보존한 채 반영 대상에서 제외합니다. 제외 후 남은 행 기준으로 수량·금액 대사와 반영 가능 여부를 즉시 다시 계산합니다.
- 연결 수량이 확인된 원본 물량을 초과하지 않도록 합니다.
- 예정수량과 실제수량을 합산하여 이중 집계하지 않습니다.
- 화면과 Excel 출력의 집계 기준을 일치시킵니다.

### 7.5 변경 근거를 남깁니다

필드별 출처, 자료 기준일, 수신일, 처리일, 변경 전후 값, 확인자를 기록합니다.

새 자료에 값이 없다는 이유로 기존 확정값을 자동 삭제하지 않습니다. 명시적 취소·정정은 별도 변경으로 처리합니다.

## 8. 판매계획 변경 처리

### 8.1 표시 방식 변경

다음 조건이 같고 총수량·총금액이 일치하는 경우, 분할·합산 표현 변경 여부를 확인합니다.

- 판매법인
- 대상 매출 월
- PO 및 제공된 PO라인
- 고객
- 모델
- 생산사이트
- 통화
- 가격 조건

같은 PO·고객·모델이라도 가격이나 사이트 등이 다르면 무조건 합산하지 않습니다.

### 8.2 실제 변경 유형

- 신규 주문
- 수량 증가
- 수량 감소
- 가격 변경
- 주문 취소
- 대상 월 이동
- 식별정보 정정
- 기존 자료에서 누락된 주문

변경 전후 수량·금액과 기존 연결에 미치는 영향을 미리 보여줍니다.

### 8.3 전체 현황과 변경분

업로드 시 다음을 지정합니다.

- 전체 현황 파일인지 변경분 파일인지
- 판매법인
- 대상 월
- 포함 사이트·지역·시트 등 적용 범위
- 자료 기준일

변경분 파일에 없는 주문은 유지합니다.

전체 현황에서 사라진 주문도 즉시 삭제하지 않고, 선언된 적용 범위 안에서 취소 또는 누락 후보로 제시합니다.

### 8.4 기존 실적과 충돌하는 감소

판매계획 20대가 12대로 감소했지만 이미 15대가 생산된 경우, 초과 생산 가능성과 연결 충돌을 표시합니다.

기존 생산·선적·매출화 실적을 조용히 삭제하지 않습니다.

## 9. 생산·선적 매칭 원칙

### 9.1 매칭에 사용하는 정보

- PO번호와 PO라인
- 모델명
- 고객명
- 판매법인 및 생산사이트
- 대상 월과 일정
- 수량 및 미배분 잔량
- 승인된 고객·모델 별칭
- 원본의 추가 식별정보

### 9.2 자동 확정 조건

필수 정보가 일치하고, 후보가 유일하며, 수량과 일정 등에 충돌이 없는 명확한 경우에만 자동 확정합니다.

PO가 있다는 이유만으로 확정하지 않습니다. 수량이 같다는 이유만으로도 확정하지 않습니다.

### 9.3 검토가 필요한 경우

- PO가 없고 후보가 여러 개인 경우
- 모델이나 고객 식별이 불명확한 경우
- 수량 배분 조합이 여러 개인 경우
- 원본끼리 일정이나 수량이 충돌하는 경우
- 신규 물량인지 기존 물량의 일정 변경인지 불분명한 경우
- 이미지 문자가 불명확한 경우

### 9.4 매칭 상태

| 상태 | 의미 |
|---|---|
| 자동 확정 | 명확한 규칙을 충족하여 연결됨 |
| 사용자 확정 | 사용자가 근거를 확인하여 연결함 |
| 검토 필요 | 후보 또는 배분을 확인해야 함 |
| 미매칭 | 적절한 주문을 찾지 못함 |
| 정보 충돌 | 기존 정보와 충돌함 |

미매칭 자료도 보관하여 이후 판매자료가 들어왔을 때 다시 연결할 수 있게 합니다.

수동 확정한 연결과 필드값은 자동 처리로 임의 변경하지 않습니다.

## 10. AI 활용 범위

### 10.1 AI가 수행할 작업

- 서로 다른 컬럼명의 표준 컬럼 매핑 제안
- 파일별 헤더명이 달라도 판매계획·생산계획·선적계획의 표준 필드 후보 제안
- 표준화된 PO·모델·판매법인·고객·대상 월·수량으로 기존 Sales Master 주문 후보와 근거 제안
- 메일 본문에서 업무정보 추출
- 캡처이미지에서 업무정보 추출
- 예정·완료·변경·취소 의미 구분
- 매칭 후보와 근거 설명

OpenAI API는 선택 기능입니다. 서버의 `.env`에 키가 있을 때만 호출합니다. 엑셀·CSV의 컬럼 추천에는 헤더명, 주문 후보 추천에는 최소 표준 식별정보와 내부 후보 ID만 사용하며 표 파일 전체는 전송하지 않습니다. 표시 없는 중간 합계 후보는 원본 전체 행과 실제 금액 대신 누락 필드, 제한된 라벨, 서버 합계 일치 여부만 전송하고 AI 분류와 서버 산술 검증이 모두 일치할 때만 제외합니다. 규칙으로 유일하게 확인되지 않은 생산·선적 후보는 `검토 필요`로만 연결하고, 양식이 달라진 후속 판매계획 후보는 `업데이트 검토`로만 저장합니다. 어느 경우에도 AI 추천만으로 주문이나 물량을 자동 확정하지 않습니다.

단, 사용자가 `메일·이미지·텍스트 입력`에 직접 등록한 메일 본문·줄글 또는 이미지는 그 내용 자체를 읽기 위해 OpenAI로 전송합니다. OpenAI는 판매계획·생산정보·선적정보에 맞춰 PO, 모델, 고객, 수량, USD 금액, 법인, PST, ETD, ETA, 선사·선박 등을 복수 레코드로 구조화하고 원문 근거와 신뢰도를 함께 반환합니다. 이 결과는 화면 검토와 원본 이력에만 저장하며 Sales Master에는 자동 반영하지 않습니다.

### 10.2 프로그램 규칙으로 수행할 작업

- 수량과 금액 계산
- 중복 처리 방지
- 배분 가능수량 검증
- 변경 이력 저장
- 자동 확정 가능 여부 판단
- 위험 날짜 계산
- 데이터베이스 반영

### 10.3 추출 검증

- 없는 값은 임의로 생성하지 않고 미확인으로 둡니다.
- 추출값마다 가능한 원문 근거를 연결합니다.
- 날짜 형식, 수량 단위, 모델 접미사를 검증합니다.
- 메일의 과거 인용문과 현재 통보를 구분합니다.
- 수신일과 업무정보 기준일을 구분합니다.
- 구조화된 출력 형식을 사용하고 서버에서 검증합니다.
- AI 실패 시 기존 데이터를 보존하고 재처리를 지원합니다.
- 문서와 메일에 포함된 명령문은 실행 지시가 아닌 입력 데이터로 취급합니다.

## 11. PSI 관리

본사에서 매주 수요일 공유하는 PSI 자료를 관리합니다.

업무 흐름은 다음과 같습니다.

DM → SA → SP → 실제 생산·선적 → ERP 매출화 확인

DM, SA, SP는 서로 다른 정보로 보존합니다.

### 관리 항목

- 발행일과 자료 버전
- 원본 주차와 주차 정의
- 연도 및 대상 기간
- 모델과 생산사이트 등 원본 집계 기준
- 주차별 DM, SA, SP
- 실제 생산·선적 실적
- 이전 버전 대비 증가·감소·이월

향후 3개월 계획을 조회하고 SP 대비 실제 선적 달성률을 확인합니다.

PSI에 PO가 없으면 임의로 특정 주문에 배분하지 않습니다. 연결 가능한 집계 수준에서 비교하고 한계를 표시합니다.

수요일 자료의 마지막 수신일과 미수신 여부를 보여줍니다.

## 12. RISK 및 확인 필요 규칙

기본 시간대는 `Asia/Seoul`입니다.

위험은 주문 전체가 아닌 영향을 받는 잔량에 적용합니다. 여러 위험이 같은 물량에 해당하면 총 영향 수량·금액을 중복 합산하지 않습니다.

| 구분 | 초기 판단 기준 | 표시 내용 |
|---|---|---|
| 생산 미완료 | 대상 월 15일부터 필요한 물량의 생산완료가 확인되지 않음 | 생산 지연 또는 생산정보 확인 필요 |
| 선적계획 대비 생산 미완료 | 선적계획은 있으나 실을 물량의 생산완료가 확인되지 않음 | 생산·선적 불일치 |
| 생산 후 선적 대기 | 실제 생산완료 후 2일 이상 경과했으나 선적계획이 없음 | 선적계획 지연 |

| 실제 선적 미확인 | 선적예정일이 지났으나 실제 선적 근거가 없음 | 선적 확인 필요 |
| ERP 매출화 미확인 | 실제 선적되었으나 ERP 매출화가 확인되지 않음 | 매출화 확인 필요 |

### 적용 세부사항

- 15일과 18일은 당일부터 적용합니다.
- 생산완료 후 2일은 초기에는 한국시간 기준 달력 날짜 차이로 계산합니다.
- 생산완료 후 2일 규칙은 18일 이전에도 적용합니다.
- 생산정보 미수신과 명시적인 미생산을 구분합니다.
- 선적계획 대비 생산 미완료는 미래 일정에도 표시하되 선적일까지 남은 기간으로 긴급도를 구분합니다.
- 월 기준 위험을 먼 미래 대상 월에 일괄 적용하지 않습니다.
- 완료·취소 상태와 부분 완료수량을 고려합니다.
- 사용자 설정으로 기준일, 대기일, 선행일, 매출화 확인 유예일, 달력일·영업일 기준을 변경할 수 있게 합니다.
- 영업일 기준을 제공할 때는 적용 휴일 달력을 명시합니다.

각 항목에는 사유, 영향 수량, 적용 기준, 경과일, 근거, 권장 확인 사항을 표시합니다.

## 13. 주요 화면

모든 화면은 흰색 카드 배경을 바탕으로 연두색 강조, 검정 본문·주요 버튼, 회색 보조정보·경계선만 사용하는 공통 색상 체계를 따릅니다. 상태 구분은 색상만으로 판단하지 않도록 기존 상태 문구와 아이콘을 유지하며, 화면 구조와 업무 기능은 색상 변경과 분리합니다.

### 13.1 대시보드

- 판매법인별 주문금액, 배송중 금액, 매출완료금액, 매출 대기, 매출예상금액을 하나의 표에 표시
- `매출 대기 = 주문금액 - 매출완료금액`
- 실제 선적되었거나 선적 일정이 있는 주문의 전체 금액을 매출예상금액으로 표시
- 금액을 선택하면 그 기준에 포함된 상세 주문을 표시
- 판매법인과 대상 월은 선택형 필터로 조회
- 우측 상단에서 화면과 같은 판매법인별 요약·상세를 Excel로 다운로드
- 전체 합계는 법인 행보다 먼저 표시하고 Excel에도 수식 캐시가 아닌 실제 합계 숫자로 첫 데이터 행에 저장

기존 업무 대시보드는 그대로 유지합니다. `/dashboard`에는 기존 인증·프로젝트 전환·왼쪽 메뉴 구조를 공유하는 별도 BuildLog 예시 화면을 둡니다. 이 화면의 지표·활동·일정은 디자인 확인용 고정 예시 데이터이며 백엔드 업무 데이터로 오인하지 않게 화면에 표시합니다. 할 일 체크만 브라우저의 임시 상태로 동작하고 새로고침하면 초기값으로 돌아갑니다.

### 13.2 Sales Master

- 주문별 통합 현황
- SO·PO를 포함한 모든 표시 열의 선택형 필터
- 모델과 고객을 서로 다른 열로 표시
- 부분 생산·부분 선적·부분 매출화 표시
- Net Sales (USD), Gross Sales (USD)를 분리하고 수량·금액 열의 현재 필터 합계를 주문 행보다 먼저 표시
- 생산·선적 칸에서 대표 예정일, 실제 완료수량, 미완료수량, 다음 일정, 일정 미정 여부와 이월 가능 수량을 한눈에 표시. 주문 수량 전체가 완료되면 예정일 미정 대신 `생산완료` 또는 `선적완료`를 표시
- 생산법인을 PST 바로 앞의 독립 열로 표시하고, PST 상세에서 예정과 실제 완료 물량·날짜를 구분해 표시
- 프로젝트 기준 날짜보다 과거인 PST·ETD가 최신 파일에 남아 있고 주문과 안전하게 연결되면 해당 행의 수량을 `실제 완료`·`실제 선적`으로 표시. 기준 날짜 당일·미래 일정과 검토 후보는 예정으로 유지하며, 수동 확정된 부분 실적은 이후 계획 누락·변경과 관계없이 보존
- 주문 기본정보와 생산·선적 상세를 수동 수정하며 수동 저장 필드는 자동 업로드보다 우선
- 안전하게 같은 주문으로 식별한 후속 판매파일의 변경은 자동 적용하지 않고 현재값·새값·수동 우선 여부를 보여 주는 `업데이트 검토`로 저장. 사용자가 선택한 필드만 반영
- `연결 상태`의 화면 명칭은 `Status`, ERP 확인의 화면 명칭은 `Closed`로 표시
- 원본 파일 다운로드와 Sales Master Excel 다운로드

화면의 판매법인 기준정보는 걸프, 사우디, 튀르키예, 레반트, 이집트, 이스라엘, 남아프리카공화국, 모로코, 인도이며 생산법인은 구미, 이집트, 인도네시아, 베트남, 중국, 폴란드입니다.

### 13.3 자료 업로드

- 첫 화면에서 판매계획·생산정보·선적정보 파일, 기준일, 전체 현황·변경분 및 적용 범위를 입력하고 대상 월은 기준일의 연·월로 자동 산정. 판매계획은 판매법인을 선택하며, 여러 판매법인 제품을 함께 포함할 수 있는 생산·선적정보는 판매법인 대신 생산법인을 선택
- 이집트·인도네시아·구미를 우선 표시하는 생산법인 토글과 현재 프로젝트 전용 판매·생산법인 직접 추가 기능 제공
- 업로드 이력에서 등록일시, 자료 유형, 원본 파일명, 범위와 처리 상태를 조회하고 원본 재다운로드
- 생산정보·선적정보는 상태와 관계없이 삭제할 수 있으며, 파일명·자료 유형·기준일과 `삭제하면 복구할 수 없습니다` 안내를 확인한 경우에만 원본·원본 행·표준화 결과·업로드 전용 매핑·연결을 한 트랜잭션으로 영구 삭제. 휴지통·숨김·삭제 이력은 두지 않음
- 사용자가 삭제하지 않은 업로드는 원본과 이력을 계속 보존. 판매계획을 삭제하면 해당 배치가 직접 만든 Sales Master 주문과 생산·선적·ERP Closed·수동값·변경 이력도 함께 영구 삭제하고 다른 판매계획 주문은 보존
- 메일 파일·이미지·메일 본문·붙여넣기 텍스트를 같은 화면에서 자료 유형별로 등록
- 판매계획은 시트·헤더 선택, 저장 설정·별칭 및 선택형 AI 보조 컬럼 매핑, 오류·누락 확인, USD 수량·금액 대사 후 Sales Master에 반영. AI에는 미해결 헤더명만 보내고 사용자가 확인하기 전에는 확정하지 않음
- 업로드 이력의 미반영 판매계획은 `Sales Master 매칭`으로 저장 원본을 다시 열어 시트·헤더·컬럼 연결을 계속할 수 있음
- 판매계획에서는 생산사이트를 직접 지정하지 않음. 생산정보의 PO·모델·행별 판매법인·수량이 유일하게 일치하고 주문 가용수량을 넘지 않을 때 생산법인과 PST 물량을 자동 연결하며, 프로젝트 기준 날짜보다 과거 PST는 완료, 당일·미래 PST는 예정으로 표시
- 생산정보의 모호한 후보·생산법인 충돌·수량 초과는 자동 확정하지 않고 검토로 보류. 선적정보는 원본과 입력 범위를 보존하며 자동 주문 연결은 이후 단계
- 같은 원본이 생산정보와 선적정보를 모두 포함하면 각 유형으로 한 번씩 등록할 수 있음. 같은 유형의 같은 파일을 다시 올리면 별도 항목을 만들지 않고 기존 항목의 파일명·기준일·대상 월·등록시각·등록자·원본·파싱 결과를 최신 입력으로 교체
- 후속 처리 규칙과 담당 대상이 불분명한 `기타` 유형은 신규 등록 메뉴에서 제공하지 않음. 이전 원본은 보존

- 검토자와 처리 이력

### 13.5 PSI

- 판매법인·생산법인·모델을 왼쪽 고정 열로 표시
- 판매법인·생산법인·모델은 각 지표 행에 반복 표시해 빈칸으로 두지 않음
- 현재 월 기준 과거 3개월, 현재 월, 미래 8개월의 12개월을 W1~W5 주차 열로 표시
- 모델마다 DM(판매계획), SA(판매할당), SP(선적계획), Inventory(예상 재고), Warehouse(실제 창고 입고) 행을 표시
- 판매법인·모델 선택형 필터와 화면 구성에 맞춘 Excel 다운로드 제공
- 사용자가 신규 PSI XLSX와 자료 기준일을 입력하면 파일명을 버전 이름으로 사용하고 자료 기준일의 연·월을 기준월로 자동 산정하여 원본·등록자·상태와 함께 프로젝트별로 보존
- 동일 파일 재업로드 시 별도 버전을 만들지 않고 기존 항목의 파일명·자료 기준일·기준월·등록자·등록시각·원본·파싱 값을 최신 입력으로 교체하고 검토 상태에서 다시 시작. 가장 최근 승인본과 모델·지표·주차별 추가·삭제·변경·순증감을 자동 비교하며 승인본이 없으면 최초 버전으로 처리
- 현재 사용 PSI와 전체 버전 이력을 분리해 표시하고 과거 원본 재다운로드와 상세 재조회 제공
- PSI 버전은 상태와 관계없이 복구 불가능하게 영구 삭제할 수 있음. 삭제 시 주차 값, RISK 검토·배분·변경 근거와 Sales Master RISK 출처도 함께 삭제하며, 남은 승인본 중 가장 최근 자료로 이후 비교 기준을 다시 계산
- 오류가 없는 버전만 사용자가 검토 후 승인하며, 승인은 Sales Master 주문을 자동 변경하지 않음
- 기준 주차까지 누적 DM 대비 SA 부족, SA 대비 SP 지연을 근거와 영향수량이 보이는 RISK 검토 신호로 표시
- 판매법인·생산법인·모델이 모두 일치하는 후보 주문을 보여 주고 사용자가 선택해 승인 또는 보류
- 승인한 PSI 신호는 Sales Master RISK 근거에 표시하되 주문수량·생산·선적·금액은 변경하지 않음
- 주문 후보 자동 확정, RISK 수량 자동 배분과 자동 조치는 아직 준비 중

## 15. Excel 출력

현재 대시보드, Sales Master, PSI는 각 콘텐츠 우측 상단의 버튼으로 실제 XLSX를 제공합니다. 장기적으로는 다음 상세 시트까지 확장합니다.

1. Sales Master: 주문별 요약
2. 생산 상세
3. 선적 상세
4. ERP 매출화 상세
5. RISK 및 확인 필요
6. 미매칭·검토 필요
7. 판매계획 및 일정 변경 이력
8. 출력 기준과 생성 시각

부분 물량은 상세 시트에서 확인하고, 요약 시트에서는 주문수량과 금액이 중복 집계되지 않도록 합니다.
